## 任务说明
修复 Skill 创作层与 RAG 知识库的割裂问题：此前只有 Agent 决策层能检索知识库，Skill 实际生成内容时完全读不到用户上传的文档（如《单立人sketch写作手册》）。通过方案 A 让 Skill 内部在调用 LLM 前主动检索并注入知识库内容。

## 完成内容
- **ComedySkill 基类增强**：
  - 新增 `retriever` 属性（默认知识库检索器）
  - 新增 `_user_vector_stores` 缓存（用户个人知识库）
  - 新增 `_retrieve_knowledge(query, user_id, top_k)`：同时检索个人库 + 默认库，自动去重
  - 新增 `_format_knowledge(docs)`：将检索结果格式化为 Prompt 文本块
  - 新增 `_get_user_vector_store(user_id)`：按需创建用户个人 ChromaDB 集合

- **全部 8 个内置 Skill 集成检索**：
  - `StandupSkill`：检索 query = `topic`
  - `SketchSkill`：检索 query = `theme`
  - `ManzaiSkill`：检索 query = `topic`
  - `JapaneseSketchSkill`：检索 query = `theme`
  - `CrosstalkSkill`：检索 query = `topic`
  - `SitcomSkill`：检索 query = `scenario + episode_theme`
  - `JokeAnalyzerSkill`：检索 query = `content[:100]`
  - `ScriptEvaluatorSkill`：检索 query = `script[:100]`
  - 所有 Skill 的 `_run()` 新增 `user_id: str | None = None` 参数
  - 检索结果自动拼接到 SYSTEM_PROMPT 尾部

- **Orchestrator 注册时注入 retriever**：
  - `register_skill()` 中，若 `skill` 是 `ComedySkill` 且 `self.retriever` 不为空，自动赋值 `skill.retriever = self.retriever`
  - 保证通过 `/chat` 和 `/skills/xxx` 两种路径调用的 Skill 都能使用知识库

- **API 路由传入 user_id**：
  - `POST /skills/standup`、`/skills/sketch`、`/skills/manzai`、`/skills/japanese-sketch` 的 `invoke()` 调用中均传入 `user_id`
  - 支持个人知识库 + 默认知识库联合检索

- **测试覆盖**：
  - 新增 `test_knowledge_injection`：验证传入 `user_id` + mock retriever 时 system prompt 会包含知识库内容
  - 新增 `test_knowledge_injection_disabled_without_user_id`：验证不传 `user_id` 且 retriever 为 None 时不注入
  - 31 个 Skill 单元测试 + API 测试全部通过
