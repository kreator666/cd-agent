## 任务说明
高频查询缓存（Redis）、多用户并发支持、限流保护。为 API 服务增加生产级的缓存、限流和并发安全能力。

## 完成内容
- 新增 `core/cache.py`：统一缓存接口（Redis + 内存兜底）
  - `Cache` 抽象基类，支持 `get/set/delete` 及 `get_json/set_json` 自动序列化
  - `RedisCache`：基于 redis-py，连接失败自动降级，带 2 秒超时保护
  - `MemoryCache`：本地 LRU + TTL 淘汰，支持 `max_size` 配置
  - `get_cache()` 工厂函数：Redis 优先，失败自动降级到内存缓存
- 新增 `core/rate_limiter.py`：统一限流接口（Redis + 内存兜底）
  - `RateLimiter` 抽象基类，滑动窗口计数器算法
  - `RedisRateLimiter`：基于 Redis Sorted Set 的分布式滑动窗口限流
  - `MemoryRateLimiter`：本地内存滑动窗口限流
  - `get_rate_limiter()` 工厂函数：Redis 优先，失败自动降级
- 新增 `api/middleware.py`：`RateLimitMiddleware`
  - 对 GET/POST/PUT/PATCH/DELETE 分别配置独立限流阈值
  - 触发限流时返回 429 Too Many Requests
  - 记录请求耗时与限流触发日志
- API 服务集成
  - `server.py` 注册 `RateLimitMiddleware`，阈值从 `settings` 动态读取
  - `core/config.py` 新增配置项：`cache_ttl` / `rate_limit_write_max` / `rate_limit_write_window` / `rate_limit_read_max` / `rate_limit_read_window`
- RAG 检索结果缓存
  - `ComedyRetriever` 新增可选 `cache` 参数与 `cache_ttl`
  - `retrieve()` 先查缓存，命中直接返回；miss 时执行检索并写入缓存
  - 缓存 key 基于查询参数 MD5，避免过长 key 问题
- SQLite 并发优化
  - `SQLMemoryStore` 对文件数据库自动启用 WAL 模式（`PRAGMA journal_mode=WAL`）
  - 提升多用户并发读取性能，减少写锁阻塞
- 测试覆盖
  - `test_core_cache.py`：内存缓存 TTL/LRU/JSON 往返，Redis 缓存（有条件跳过）
  - `test_core_rate_limiter.py`：内存/Redis 限流器窗口过期、键隔离、超限阻断
  - `test_api_middleware.py`：GET/POST 限流通过/阻断、OPTIONS 不限流
