## 任务说明
主模型失败（超时/限流/异常）时自动降级到备用模型（如 API 故障 → 本地 Qwen2.5-72B）。

## 完成内容
- **core/config.py**: 新增三层 Fallback 备用模型链环境变量（逗号分隔）
  - `CREATIVE_FALLBACK_MODELS`（默认 `gpt-4o,qwen-max`）
  - `ANALYTICAL_FALLBACK_MODELS`（默认 `qwen-max,gpt-4o-mini`）
  - `FAST_FALLBACK_MODELS`（默认 `qwen-turbo,ollama-qwen2.5`）
- **models/factory.py**: 新增 `get_model_with_fallback(name, task_type, **kwargs)` 方法
  - 基于 LangChain `RunnableWithFallbacks` 实现自动降级
  - 主模型失败时依次尝试备用模型链
  - 不可用的备用模型被自动跳过并记录 warning 日志
  - 所有异常类型（`Exception`）均触发 fallback，可根据需要细化
- **所有 Skill 统一接入 Fallback**
  - 6 个内置 Skill + 插件 loader 统一改用 `get_model_with_fallback(task_type=self.task_type)`
  - 向后兼容：保留 `get_model()` 方法，Orchestrator 初始化等场景不受影响
- **测试覆盖**
  - `test_get_model_with_fallback_returns_runnable`: 验证返回 `RunnableWithFallbacks`
  - `test_get_model_with_fallback_empty_fallbacks`: 验证空备用链只包装主模型
  - `test_get_model_with_fallback_ignores_unavailable_fallback`: 验证不可用备用模型被跳过
  - 更新 `test_skills_standup.py` mock 目标为 `get_model_with_fallback`

## 备注
- Fallback 机制对 Skill 调用方完全透明，`prompt | llm | invoke` 链式调用无需改动
- 用户可通过 `.env` 自定义备用模型链，例如 `CREATIVE_FALLBACK_MODELS=gpt-4o,qwen-max,ollama-qwen2.5`
- 若所有模型均失败，`RunnableWithFallbacks` 会抛出最后一个异常
