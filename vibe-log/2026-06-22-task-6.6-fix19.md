## 任务说明
用户反馈：在「总编」按小节生成阶段，多次修复后仍然不能按意图写作——经常出现「覆盖第一次的一小节，第二次就结束了」的情况。用户期望能像和主编聊天一样，每次指令可以让系统写下一段、修改当前段/上一段，直到明确说「完成」才结束。

本次任务把原来简单的「继续 / 修改 / 完成」关键词匹配，升级为更自然的四意图分类：`finish` / `next` / `prev` / `modify`。

## 完成内容
- 新增 `_classify_section_reply` 方法，识别用户在分段生成阶段的自然语言指令：
  - `finish`：完成 / 结束 / done / 停 / 好了 / 定稿 / 就这些 / 到此为止
  - `next`：继续 / 下一段 / 下一节 / 第二节 / 往后 / 推进 / 往下写 / next / go on 等
  - `prev`：上一段 / 上一节 / 前一段 / 回到上一段
  - `modify`：修改 / 重写 / 太平 / 加梗 / 套话 / 说教 / 幽默 / 吐槽 / 攻击性 / 节奏 / 情绪 等质量/风格反馈
- 简短确认语（ok / 好的 / 可以 / 行 / 没问题 / 就这样 / 确认）仍视为推进；
  但如果是长句（如「可以，但再加点攻击性」），会按 modify 处理。
- `next` 时如果用户附带风格要求（如「下一段加点吐槽」），会把剩余文本作为 feedback 传给下一段。
- `prev` 时回退索引并带上用户反馈重写上一段。
- 去掉「最后一段继续自动结束」的逻辑，只有 `finish` 才进入 `done`。
- 新增 3 个回归测试：
  - `test_natural_language_next_with_feedback`
  - `test_natural_language_prev_section`
  - `test_natural_language_modify_current_section`
