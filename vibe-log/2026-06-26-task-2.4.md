## 任务说明
用户反馈三个问题：
1. `PlannerAgent` 结构化输出失败，fallback 文本解析也失败，最终使用默认大纲。
2. 交互输出需要像专业版一样结构化：`给用户的反馈` / `当前处于什么状态` / `提示用户应该做什么`，其中后两部分由 Planner 生成的 Todo + Outline 汇总后返回前端。
3. 每次收到用户输入，优先判断是否为 `@话题/态度/偏见/情绪` 等明确槽位行为。

## 完成内容
- `PlannerAgent` 改用普通文本输出 + 稳健正则解析：
  - 去掉 markdown 代码块标记
  - 按 `todo` / `outline` / `tone` 分段
  - 支持编号和 bullet 列表
  - 解析失败时使用默认大纲兜底
- 新增 `plan_review` / `routing_plan_feedback` 阶段：
  - `PlannerAgent.run()` 完成后进入 `plan_review`
  - `plan_review_node` 调用 `interrupt()` 暂停，payload 包含 todo / outline / tone
  - `process_plan_feedback_node` 解析用户反馈：
    - “开始/确认/写” → 进入 `writing`
    - “重新规划/换” → 回到 `planning`
    - 其他 → 视为修改意见，回到 `planning`
- `SupervisorAgent` 与 `supervisor_graph.py` 接入计划审阅链路：
  - `planning -> planner`
  - `plan_review -> plan_review_node -> process_plan_feedback -> supervisor`
- `/pro/chat-v4` 接口：
  - 检测到当前 phase 为 `plan_review` 时，使用 `Command(resume=message)` 恢复
  - `_build_response` 识别含 `outline` 的 interrupt payload，返回 `workflow_state=plan_review`
  - 响应内容结构化：`给用户的反馈`、`当前处于什么状态`（含槽位/Todo/大纲）、`提示用户应该做什么`
  - `next_actions` 提供 A/B/C：开始写作 / 重新规划 / 修改计划
- `entry_node` 增加 `@` 预检：
  - 若用户输入包含 `@话题/态度/偏见/情绪`，直接返回 `fill_slot` + `filling_slots`
  - 不调用 LLM，避免 token 浪费且行为明确
- 测试：
  - 新增 `tests/test_entry_node.py` 覆盖 `@` 预检
  - 更新 `test_state_machine.py`、`test_interrupt.py`、`test_phase1_full_flow.py` 适配 plan_review 中断
  - 新增 `test_pro_v4.py` 中 plan_review 与 resume 场景
